Final report
What was actually broken
Nothing worked at all when I started. .env pointed at 13306/music_streaming/sohail; MySQL runs on 3306/music_discovery/root. Every catalog endpoint returned HTTP 500, and the frontend hid it (call() swallows failures → empty shelves). Fixed first; the old values are kept commented.

Your 10 bugs → 4 root causes
Bugs 4, 5, 6 were one line. usePlay enforced the free tier's on_demand_playback entitlement by calling setShuffle(true), replacing your startIndex with Math.floor(Math.random() * items.length), and firing a toast — on every play. Reproduced twice before fixing: clicked "Gehra Hua" → played "Move - Yeh Ishq Ishq"; clicked "Dhurandhar - Title Track" → played "Teri Ni Kararan". Removed. A silent substitution is indistinguishable from a broken player. The entitlement still feeds the plans table; re-gating needs a visible dialog, not a swap.

Bug 7 — premium was decorative. PlaybackService clamped quality on /stream only. SongResource emitted songs.preview_url raw — the top of the ladder (_320.mp4) — so every album, search and shelf payload handed a free account a premium URL. New AudioAccess clamps at that boundary. Free/guest/expired now get _96, Premium gets _320, downloads 402/401. My own test caught a leak here: memoising the ceiling in one slot served a guest's tier to the Premium user behind them — it's keyed by user id now.

Bug 3 — album tracklists changed while browsing. Caught live: the Dhurandhar album showed 11 tracks including "Shararat", which belongs to a different album; minutes later, 10 without it. resolveAlbumForSong rewrote album_id from whatever album name the incoming payload carried, and a search result names a release differently from the tracklist a song sits on. Membership is now authoritative-only (trackNumber present ⇒ it came from a real tracklist), and a legitimate move clears the stale track_number — which is what left 4 tracks all claiming position 1.

Bug 2 — "Top songs today" was a 7-day score. It read trending_score (7-day sum, 48h half-life). New songsToday() counts plays since local midnight; below 4 plays it returns nothing and the shelf retitles itself "Trending this week" rather than lying. history now accepts guest plays (nullable user_id + session_id), and a play only counts past 30s / 50% — client and server both enforce it. Live proof: 7 plays today, exactly one with ms_played=30203, while dozens of few-second test skips recorded nothing.

Bug 1 — dashboard albums. "New releases" was headed by albums dated 2028-01-01 and 2027 (provider year-only metadata → Jan 1). newest now excludes unreleased rows.

Bug 10 — queue survives in-app navigation and a reload now (persisted; restores paused, since autoplay without a gesture is blocked). Bugs 8, 9 were already built — the gaps were Media Session and keyboard shortcuts, both absent, both added.
